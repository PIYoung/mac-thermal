# Permission and unavailable-state verification

Mac Thermal does not require an administrator helper, fan-control permission or Full Disk Access for its ordinary resource dashboard. Unavailable sensor/process values remain unknown; the app must not invent a zero or a successful operation.

| Area | Expected behavior without access/readiness | Automated coverage | Real-system boundary |
| --- | --- | --- | --- |
| Apple on-device explanations | Show basic current-state, evidence and suggested actions. Do not start inference when unavailable. Explain OS requirement, disabled Apple Intelligence, model preparation, unsupported device/language or generic unavailability. | `health_advice_probe`: generated evidence-ID coverage, six unavailable states across five tabs/four languages, no engine calls, guidance retained, reason-specific generation failures, one bounded busy retry, timeout/retry cancellation, transient/sustained/critical resource constraints, and four-language partial-response filtering. | Actual on-device generation with constrained evidence IDs was verified on this Mac for this release. The initial disabled-model availability was also observed. Tests do not toggle global Apple Intelligence, download a model, or reproduce every OS/device combination. This API uses model availability rather than an app-specific permission dialog. |
| Codex local records | Show unavailable instead of stale counters or a false zero; retain the ordinary resource dashboard. Retry after access returns. | `codex_monitor_probe`: an owned fixture directory is made POSIX-unreadable; the OS open fails, old values clear, restored access is re-enumerated on the next scan. Missing/replaced/symlink roots are also tested. | POSIX denial is not a fresh-install macOS TCC dialog test. Real Codex files, conversation contents and user permissions are not changed by the probe. |
| Disk cleanup | Reject an inaccessible selected folder; keep files untouched. Report failed/skipped moves truthfully. | `disk_cleanup_probe`: real POSIX denial and recovery on an owned temporary directory; injected Trash failures/cancellation and exact review boundaries. UI probes inject scan/execute operations. | No real user file is moved. Home-folder TCC allow/deny/revoke dialogs and OS calls blocked on a pending dialog have not all been exercised end to end. A scan awaiting an OS call may wait for the user's response. |
| Quota reset notifications | Keep alerts off if authorization is denied, undetermined or unavailable. Saved opt-in must not trigger a permission prompt or post an alert on launch. Other features remain available. | `codex_reset_notifications_probe`: fake authorization transport covers denial, late approval, restart with permission absent, delivery failure and duplicate suppression. | No real permission prompt, notification or future account-reset event is generated by the probe. OS Focus/lock-screen presentation is not proven by these fixtures. |
| Launch at login | Display off or approval-needed accurately. Manual app launch and its dashboard remain usable without login-item approval. | `health_advice_probe`: injected login off/pending/enabled states, four-language labels and available AI-help entry. | Actual `SMAppService.register()` rejection, fresh-login startup and system approval/revocation are not simulated by the label fixture and are not claimed as tested. |
| Resource sensors/process ranking | Keep working metrics visible; show unknown/skipped entries where data cannot be read. | Existing thermal/GPU/fan/component-temperature probes cover missing/invalid sensors; process ranking fixtures cover unreadable processes and sampler failure. | Hardware-specific readings and every managed-Mac restriction cannot be established from mocks. |

A downloaded community build is ad-hoc signed and not Apple-notarized. If macOS blocks launching it, the process cannot run to show an in-app fallback. Code-signature verification does not prove Gatekeeper acceptance on a fresh Mac. These tests do not weaken or bypass Gatekeeper.

The probes use isolated preference suites and owned temporary files. They do not reset TCC, change login-item registration, revoke notification permission, change Apple Intelligence settings, request Full Disk Access, or access another user's files. Global/real permission changes require separate user review under AGENTS.md.

Run the focused checks:

```sh
zsh scripts/run_health_advice_probe.sh
zsh scripts/run_codex_monitor_probe.sh
zsh scripts/run_codex_reset_notifications_probe.sh
zsh scripts/run_disk_cleanup_probe.sh
```

The full regression command is `zsh scripts/check.sh`. A passing fixture verifies the specified application behavior; it does not prove that every macOS permission dialog has been exercised.
